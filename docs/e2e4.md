# Follow a pawn from e2 to Play

Start with White to move. Lift the pawn on e2, then put it back. Lift it again and place it on e4. Both attempts begin with the same sensor reading. Which one should give Black the move and add an entry to Undo?

**At the board.** A Hall sensor detects the magnet over a square. The firmware knows which piece belongs there from the game position. In the launch board’s normal orientation, e2 is square 52 and e4 is square 36. Both connect to the PCA9555 at `0x23`, on pins 4 and 12 respectively. The firmware reads all four expanders before publishing a new 64-square occupancy map. [Sensor map](../config/hardware/sensor_map.yaml#L72-L88) · [Scan and decode](../src/pca9555_input_scan.cpp#L178-L200)

**While the pawn is in your hand.** The board looks up legal destinations from e2. With legal guidance enabled, e3 and e4 are available. Returning the pawn to e2 cancels the pickup. White still has the move and Undo is empty. Placing it on e4 instead lets the firmware submit `e2e4` to Litch-Max. Once the engine accepts it, the board records one Undo entry and Black is up. [Legal destinations](../src/game_persistence_coordinator_legal.cpp#L312-L321) · [Move acceptance and Undo](../src/game_persistence_coordinator_apply_human.cpp#L43-L63) · [Virtual board journey](../test/test_empty_piece_led_virtual_litch_journey/test_main.cpp#L417-L461)

**On Play.** Firmware sends the position and physical occupancy together. Flutter assembles all ten fragments of one board revision before publishing it. Play can therefore distinguish a pawn in hand from a pawn that has landed. At the end of the move, e2 is empty, e4 holds the white pawn, and the side to move is Black. [Firmware publisher](../src/firmware_home_state.cpp#L29-L47) · [Flutter assembler](../app/lib/src/models/home_state_wire_codec.dart#L490-L525) · [Play’s square rendering](../app/lib/src/widgets/home_chessboard.dart#L491-L542)

Run the board journey from the Litch root on macOS or native Linux with Python 3.9 or newer and a C++17 compiler.

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install platformio==6.1.19 esptool==4.9.0
./litch bootstrap firmware
./litch test native --filter test_empty_piece_led_virtual_litch_journey
```

With Flutter 3.41.2 installed, continue through the native board bridge to Play on both simulated phone platforms. The bridge supplies the Hall readings, so you can run the journey without a board or phone. [Flutter setup](../app/README.md#building-from-source) · [Play journey](../app/test/virtual_litch_mode_latency_test.dart#L833-L862)

```sh
./litch bootstrap flutter
PLATFORMIO_BUILD_DIR="$PWD/.pio/interactive-sync/build" \
  pio test -e native -f test_virtual_litch_app_bridge_manual --without-testing
LITCH_VIRTUAL_BRIDGE="$PWD/.pio/interactive-sync/build/native/program" \
  python3 tools/qa/interactive_sync.py --profile focused \
  --test test/virtual_litch_mode_latency_test.dart \
  --plain-name 'modern Store occupied refusal, retry and physical mode following'
```
